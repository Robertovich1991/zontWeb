### Important data nuance (device clock vs server clock)
The `timestamp` field (device-reported GPS time) is unreliable and often stale — e.g. `350317176004061` and `350317175915150` are actively transmitting (receivedAt = now) but report device `timestamp`s of 2026-11-13 / 2026-11-14. Online/offline must be judged by **`receivedAt`** (server reception time), NOT `timestamp`. This does not affect the target IMEI (it has no rows at all), but matters if the app's "online within ~5 min" logic keys off `timestamp` instead of `receivedAt`/`updatedAt` — that would mislabel live devices as offline. Flagging for awareness.
